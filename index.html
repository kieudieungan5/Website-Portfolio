Concurrent Banking Transactions Processing

To ensure transactions processed concurrently but update balances correct & prevent deadlock, I tried with 4 versions:

V1/ ExecutorService & pool to implement multithread; Future to store result of task, needed to detect error tasks

V2/ synchronized & account instance's lock to lock code block of updating balance

V3/ AtomicLong.incrementAndGet() to create lock id for account instances, thread acquires locks in ascending order

V4/ Connection, PreparedStatement to connect Java application & MySQL; setAutoCommit(false), commit() & rollback() support atomic transactions; InnoDB, "UPDATE...WHERE...AND..." locked row of transaction. But still need checking case of transactions update rows in different orders & cause deadlock.
